# Memory & recall (companion)

Talk can recall what Raiz said before ("what did I say about the migration last week?") and keeps
durable facts about him ("my cat is Mochi", "I want to run 3× a week"). **SQLite is the source of
truth** (Raiz's decision, 2026-11-15); Obsidian gets a generated, read-only view. Everything stays on
the laptop.

## Layers

1. **Episodic index** — every transcript (normal notes and talk turns), talk reply and diary page,
   chunked (~1–3 sentences, one note per chunk when short) with its local date/time and source id.
   - **Keyword**: SQLite FTS5 (BM25) — exact names, projects, rare words.
   - **Meaning**: a small local **multilingual** embedding model on CPU (Raiz mixes Indonesian and
     English; pick one that handles both, e.g. multilingual-e5-small or similar — check size/speed
     on this laptop). Vectors stored in SQLite; brute-force cosine is fine at this scale
     (≈5–10k notes/year).
   - **Hybrid ranking**: merge both result lists (e.g. reciprocal rank fusion), prefer recency on ties.
   - Indexed right after transcription (and on diary build); a one-time backfill for the archive.
2. **Distilled facts** — durable facts about Raiz with provenance:
   `{id, text, topic, kind (fact|preference|goal|decision|person|place), source note ids, first_seen,
   last_confirmed, confidence, status (active|corrected|retired), history}`.
   - Extracted by piggybacking on Codex calls that already happen (the talk turn's JSON; the diary
     build for normal notes) — no extra LLM pass per note.
   - New facts that contradict an existing one don't silently overwrite it: the old one is retired
     with history, or the assistant asks when unsure.
   - Goals are facts of kind `goal`; a future goal tracker links progress reports to them.
3. **Tags** — people / places / projects / topics per note (from the same extraction), used for
   filters ("only notes mentioning Mochi") and for Obsidian links.

## Use in Talk

- Every turn: retrieve the relevant **facts** + top **episodic** hits for the transcript and add them
  to the prompt with dates ("on 3 Nov you said …"). Never present a recalled item without its date.
- Explicit recall questions get a bigger retrieval budget and may use one detail round (like the
  workspace evidence round).
- Honest uncertainty: if nothing matches, say so — never invent a memory.

## Corrections & control

- Web UI **Memory** panel (loopback only): search, view facts with their sources, edit, retire,
  delete; delete also removes a fact from future prompts immediately.
- By voice: "that's wrong, my cat is Mochi not Mocha" → proposed `memory_fact` change → confirm.
- "Forget X": proposed action (confirm) that retires the matching facts and excludes matching
  episodic chunks from retrieval (the raw notes themselves are never deleted by this).

## Obsidian view (generated, read-only)

- `<vault>/<diary_folder>/../Orbit/Memory.md` (or a configured path): facts grouped by topic, each
  linking to the day it came from (`[[2026-11-14]]`); header: "Generated by Orbit — edit at
  http://localhost:8765/ui/". Rebuilt when facts change.
- Diary pages get `[[Topic]]` links from the tags, so Obsidian's backlinks/graph show every day a
  person/project was mentioned.

## Not now

- Mood/energy stays its own quiet store (docs/talk.md), but may share the index later.

## Implementation

Code: `companion/src/orbit_notes/memory.py` (index, search, recall, facts, view), `memory_api.py` (web UI API),
web `MemoryPanel.svelte`. Tests: `companion/tests/test_memory.py` (a fake hashing embedder from `conftest.py`, so
tests never download a model).

### Episodic index (step 1)

- **Storage**: `<data_dir>/memory.sqlite` (WAL), separate from `index.sqlite`. Tables: `chunks` (source
  `note | reply | diary | reflection`, ref = note id or date, local date, `at` with the watch's offset, text,
  `excluded`, `vec` float32 BLOB), `chunks_fts` (FTS5, `unicode61 remove_diacritics 2`, rowid = chunk id),
  `sources` (sha of each indexed text → unchanged sources are skipped), plus `facts`, `tags`, `forgotten`, `meta`.
  Everything except facts/tags/forgotten can be rebuilt from the notes on disk (`memory backfill`).
- **Chunks**: a note ≤ 480 chars is one chunk; longer text is split into ~1–3 sentences (≤ ~320 chars, run-on
  speech split at word boundaries). Diary pages: only the page's own prose (orbit block before `## Notes`,
  no headings / `**Mentions:**` line); reflections from `data_dir/reflections/`.
- **Model**: `multilingual-e5-small`, int8 ONNX export `Xenova/multilingual-e5-small` (pinned revision), run
  with `onnxruntime` + `tokenizers` — both already installed for faster-whisper, so **no new dependency**.
  118 MB, downloaded once into the Hugging Face cache (`~/.cache/huggingface/hub`, next to whisper's model).
  384-dim, e5 `query:` / `passage:` prefixes, mean pooling. `memory_embedder = "none"` → keyword search only.
  Measured on this laptop (load average ~6–15): load 1.6–2.5 s; 92 chunks in 2.6 s (4 threads); one query
  ~10 ms. Chosen over fp32 e5-small (470 MB, same quality), e5-base int8 (279 MB, worse on this archive, 10×
  slower) and paraphrase-multilingual-MiniLM (worse ranking) on a small labelled set of real notes, including
  Indonesian queries against English notes.
- **Lazy & cheap**: `serve` starts without loading the model. Text goes into FTS immediately (any process, e.g.
  the `diary` cron); a background thread in `serve` (nice +10, one ONNX thread on that thread) catches up
  with the archive at start, indexes each note after transcription (and its talk reply after the turn), and
  fills missing vectors. A talk note warms the model while whisper runs.
- **Search** (`Memory.search`): FTS5 BM25 over content words (English + Indonesian stop words, question and
  date words dropped; words ≥ 4 chars as prefixes) + brute-force cosine over all vectors (cached matrix),
  merged by reciprocal rank fusion (k = 60), up to 2 chunks per source, recency breaks ties. Short questions
  are embedded as their content words (the question wording otherwise outweighs the topic). The model's
  cosine scores are compressed (unrelated queries still score ~0.83 here), so there is **no similarity
  floor**: everyday Talk turns use keyword-confirmed hits only; explicit recall shows the top hybrid hits and
  Codex judges them (see Recall).
- **Date ranges** in questions (`parse_range`): today / yesterday / kemarin, N days ago, last / past N days,
  this / last week (Mon–Sun), this / last month, "in October", "on Monday" (EN + ID). A range with no topic
  ("what did I say last week?") lists that period: diary prose and reflections first, then his notes.
- **Backfill**: `orbit-notes memory backfill [-c config] [--threads 4]` (incremental; prints timings and index
  stats); `orbit-notes memory search "…" [--from --to]` for a quick check. `serve` does the same catch-up in
  the background.
- **API** (loopback only, under `/ui/api`):
  ```
  GET /memory/search?q=&limit=20&from=YYYY-MM-DD&to=YYYY-MM-DD&tag=Name
    200 {"query": "…", "hits": [{id, source, ref, note_id, local_date, at, mode, text, score, sim, keyword,
                                 when: "Tue 03 Nov 2026 21:14", label: "voice note"}]}
  GET /memory/status   → {chunks, embedded, excluded, first_date, last_date, facts: {status: n}, tags,
                          forgotten, bytes, model}
  ```
  Web UI → **Memory**: search box (+ optional date range) with dated results.

### Recall in Talk (step 2)

- Every turn (`Memory.turn_evidence`, called from `Talker.respond`): a **MEMORY** section after the other
  evidence: the known facts (step 3) and episodic hits, each line `- Tue 03 Nov 2026 21:14, voice note: "…"`
  (labels: voice note / talk turn, his words / Orbit's reply to him / diary page / his saved reflection).
  The current note and the other turns of its conversation are never "recalled" (already in the session).
- **Everyday turn**: up to 3 hits that share a content word with the transcript (keyword-confirmed), ≤ ~1500
  chars; "No earlier notes matched this voice note closely." otherwise.
- **Explicit recall question** (`RECALL_RE`: remember / did I say / what did I / when did I / ingat / pernah /
  kapan aku / aku bilang apa …): up to 10 hybrid hits, ≤ ~4500 chars, restricted to a date range the question
  names; a range with < 4 hits is filled with that period's diary prose and notes. The section states the
  covered span ("his notes from Sat 14 Nov 2026 to Sun 15 Nov 2026 (45 notes)") and that a hit is not
  necessarily about what he asks; with no hits: "NOTHING in his notes matched this. Say plainly that you have
  no memory of it …".
- **Detail round**: `need_details.recall: [{query, from, to}]` (≤ 3 searches; dates `YYYY-MM-DD` or "") →
  `RECALL SEARCH "…" between … and …:` + up to 10 dated hits each, in the same single detail round as the
  workspace / insight details.
- Rules (sent every turn): never present a recalled item without its date; if MEMORY does not answer a question
  about the past, say there is no memory of it; never invent one; try the other language (ID/EN) in a detail
  search. The old rule "the AI model … memory of past days: fixed" now says the past reaches Codex through MEMORY.
- A memory failure never fails the turn: Codex is told "MEMORY: could not be searched right now (…)".
- `talk.py` touch points: `import memory`; `RULES += memory.RECALL_RULES`; `memory.extend_recall_schema(OUTPUT_SCHEMA)`;
  `MEMORY_DETAILS` in `wants_details`; `Talker(mem=…)` + `self.memory.warm()` in `warm()`; two evidence lines in
  `respond()` (turn + detail round).
